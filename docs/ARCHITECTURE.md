# Architecture

V0 foundation is implemented and locally exercised; final evidence lives in VALIDATION. Next.js 16 is the sole web/application runtime, with React UI and server-only identity/mail/database boundaries. PostgreSQL persistence is shared through Drizzle. This is a modular monolith, not separate frontend/backend services.

```text
Browser -> apps/web (Next routes / components / server modules)
                      |-> Better Auth 1.7.7 -> Drizzle -> PostgreSQL
                      |-> SMTP (verification/reset/deletion email)
packages/database -> typed schema, client, explicit migration tooling
```

Only two workspace packages exist: `apps/web` and `packages/database`. Web `src/server` owns environment validation, auth, sessions, mail and sanitized logging; `src/lib` contains branding/i18n/client helpers; components and app routes compose the UI. Database schema/client are not imported into browser bundles. Secrets remain server-side.

English/Vietnamese core pages and next-themes are presentation concerns; auth/persistence stay authoritative on the server. Transactional emails are English-only; database preferredLocale is read-only/reserved with default en. Locale-scoped root layouts own HTML language/providers/shell; native locale/account links cross document boundaries rather than assuming shared root-layout client navigation. Session/role guards must run at each protected server entry point, not merely hide UI.

V1 catalog is implemented as `features/catalog/contracts`, `server/catalog/{service,repository,projection,provenance,errors}`, actual Node API routes, public/admin locale pages and catalog components. Server service authorization precedes privileged parsing; repository transactions enforce revision/child/source/audit atomicity; public projection filters private metadata and unpublished relation targets. Batch child loads and PostgreSQL FTS/trigram indexes support bounded local search. Database schema remains separately modular; pure `catalog-types` constants can cross into presentation, never the connection/auth/database runtime.

Catalog local acceptance gates passed (`V1_VALIDATION.md`); hosted acceptance is unverified. Same-locale client links are kept; auth transitions have one router replacement rather than an immediately competing refresh. Development uses supported webpack and explicit workspace-package transpilation; production uses `next build`. Development compilation latency is not a production performance claim.

## V1 final-review correctness boundaries

`selectDisplayTitle` is shared by cards/detail projections and related-work links. Related targets' visibility and JSONB-aggregated title candidates are read in the **same SQL statement**, never by a later unqualified title query; a concurrent hide/private edit therefore cannot inject newly private title metadata into an already qualified relation result. The shared policy is: canonical Work title if its language matches the requested locale, otherwise curated PRIMARY for that locale, otherwise ORIGINAL (declared original language preferred), otherwise canonical. ALIAS never becomes display fallback. Codepoint language/title tie-breaking is explicit, independent of PostgreSQL row order; database uniqueness normally permits only one localized PRIMARY and ORIGINAL. EN/VI interfaces may display an original title in its actual other language when localization is absent.

All public slug and search reads (including search count/IDs and every child query) run in read-only REPEATABLE READ transactions. A request spanning a concurrent hide/private edit can return its consistent earlier public snapshot, never newly private child metadata. Admin loading and writers do not inherit read-only transaction wrappers. UNKNOWN cover asset paths remain absent publicly, but authorized admin DTOs retain them so editing an unrelated field does not silently clear metadata or change its attribution.

Full updates still lock/compare revision and commit source/children/history together. Exact unchanged child assertions retain their source IDs and stable title/identifier/credit identities; editions retain their supplied, work-owned UUIDs. Name-only credit reuse is confined to this Work's exact prior role/edition/name assertion, never global creator-name deduplication. Ordering-only credit changes do not re-cite bibliographic identity. New/modified assertions use the edit citation. Compound Work/Edition/cover records additionally append changed scalar evidence in `catalog_field_evidence`; unchanged values retain earlier evidence even when a publisher/credit is amended. Null assertions record removals, and edition/cover existence assertions distinguish absent from empty metadata. Actor and decision remain in the same-revision transactional audit.

`works.source_id`/the existing public `source` DTO identify the latest editorial submission, **not a blanket citation for all unchanged values**. For compound rows, row source means latest record amendment; field evidence is authoritative for individual scalars. Child source IDs and field/audit internals are not added to public DTOs. Legacy evidence is lazily bootstrapped from currently stored rows on their first new update; it cannot certify or restore attribution silently overwritten by older releases. No historical audit or applied migration is rewritten.

Publication is an administrator decision, not a client-controlled role. All commands targeting PUBLISHED (including edits staying published and visibility restoration) require strict `publicationReviewAcknowledged: true` at server contract/service validation and repository guards. The UI supplies the current unchecked-by-default checkbox value; the transactional audit records the explicit attestation with the server session actor. This is stronger than the former UI-only reminder, but **not independent factual/copyright/content-rating verification**; authorized humans can assert falsely. Draft/hidden edits do not require this attestation.

### Nonblocking future improvements (not V1 expansion)

A privileged per-field citation/history viewer; indexed/bounded latest-evidence retrieval and measured query plans for long histories; explicit corroboration/retraction commands for unchanged facts; review-policy versioning/structured content ratings; source/audit retention and operational tamper resistance. These remain separate follow-ups, not a feed/social implementation. V1 has since merged; V2 starts under its separate milestone acceptance.

V1 is merged at `11d544a` with successful post-merge CI. V2A adds modular `features/ingestion/{contracts,providers}` and `server/ingestion/{service,requests,jobs}`; local acceptance and actual PR/push GitHub CI are verified at `e1aba9e` in `V2_VALIDATION.md`. Request input is private and is not a Work or proof of identity. V2B searches only separately reviewed public-summary title/aliases for authenticated users; raw request titles/notes/identities/history remain owner/admin-only. Equal normalized titles never merge requests or Works. Request creation/amendment/cancellation writes revision, append-only events and durable intent atomically; content input revision is distinct from moderation revision. User deletion detaches nullable ownership/actor FK while retained private history uses opaque actor snapshots (not a promise of full data erasure).

V2B adds pure `features/ingestion/support` contracts, server-only `server/ingestion/request-public`, guarded request HTTP routes and dynamic/noindex EN/VI request pages. Owner DTOs retain private input/history; followed/search DTOs are allowlisted summaries with actual counts and only published visibility-qualified Work slugs. Owned detail uses `getRequestInTransaction` inside the same REPEATABLE READ transaction as ownership/count/slug selection: no nested global pool acquisition or split snapshot. Pagination counts/items share this snapshot. Reviewed title/alias keys never derive from raw title/notes/evidence. Request-first locking and unique(user,request) protect concurrent support; blind own-scoped unfollow reveals no request existence. Amendment/cancellation invalidate reviewed metadata and search atomically, leaving redacted followed state. UI submission retries preserve UUID delivery identity; optional title/format prefill is not bibliographic proof. Bounded same-locale request sign-in return paths preserve the protected destination without opening external redirects. V2B is locally verified by147 units/51 actual SQL cases, all five distinct browser cases across two isolated development sessions, optimized production build and real anonymous loopback production smoke. An initial combined4/5 run timed out at native owner reload after development-worker memory exhaustion; no single local5/5 pass is claimed. V2B is locally and actual-CI accepted at `147d1b3`, with all mandatory gates and five Chromium cases together passing on both PR/push CI; PR #2 remains open/unmerged, and loopback HTTP is not hosted TLS/authenticated-production proof.

The PostgreSQL queue has bounded SKIP LOCKED claims, atomic attempts, ownership/token/expiry fencing after row-lock waits, lease recovery, capped exponential backoff, dead letters and idempotent enqueue. Claim locks jobs only; request mutations lock request before cancelling its jobs. A later processor must follow request-before-job order and revalidate input revision and lease before candidate/request commits. Processing failure is a job state, not an automatic request rejection. Atomic per-provider budgets reject missing, disabled, unapproved or unknown-limit policies. No browser-session worker, infinite serverless worker, active provider, scheduled fetch or automatic publication exists in V2A. V2C must add bounded execution behind this same shared pipeline; Vercel Hobby daily cadence is the maximum planned cron frequency, not a deployed claim. Library/progress and communities remain separate planned domains.

Deployment uses one web runtime and PostgreSQL/SMTP, explicit pre-deploy migrations, a pooled runtime DB URL and direct migration URL. Do not initialize DDL during requests or startup. Liveness `/api/health` and bounded DB/schema readiness `/api/ready` are implemented; V2A durable intent is locally and CI verified; V2B is locally and actual-CI accepted at `147d1b3` with PR #2 open/unmerged, and hosted/serverless recovery remains unverified.
