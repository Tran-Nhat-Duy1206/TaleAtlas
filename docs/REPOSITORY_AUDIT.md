# Reference repository audit

## Scope and evidence

Read-only audit of `E:\TaleAtlas-references\StoryNest` and `E:\TaleAtlas-references\Eiren`. Complete tracked path inventories were inspected with `git ls-files`; targeted source and documentation were read with glob/read/grep. Graph access was unavailable. No reference files were modified, dependencies installed, applications started, migrations applied, or tests executed. Findings are source-established risks, not reproduced exploit or current test-run claims. Evidence below uses repository-relative paths and line numbers.

## Structure and architectural fit

- **StoryNest:** compact CommonJS Express/PostgreSQL application: `server.js` (2,885 lines) owns authentication, SQL adapters, library CRUD, search orchestration, community and integration routes; `database.js` owns runtime DDL. `api/index.js`/`vercel.json` provide serverless deployment. Six static HTML pages, one CSS sheet and page-oriented vanilla JS controllers live under `public/`; VI/EN strings are in `public/i18n.js`. Two services (`mangadex`, `mangaSearchService`), one genre utility, migration/health scripts, two tracked test files and `.storynest/*` planning/API/schema/bug documentation complete the product structure. Useful reader UX/domain reference; unsuitable security/persistence foundation without redesign.
- **Eiren:** TypeScript ESM modular Discord monolith, not a reading app. `src/app` assembles runtime/services/registry and DB validation drivers; `src/core` contains config, database, permissions, dispatchers, errors, logging and operations; `src/dashboard` contains auth/access/read services and server-rendered management views. `src/modules` comprises core, moderation, logging, verification, antiraid, roles, tickets, reports, suggestions, levels, reputation, starboard, profiles, events, giveaways, tempvoice, achievements, analytics, AI, automation, data-retention and subject-requests. Cross-cutting repositories/services are separate. Twenty-one SQL migrations (`0000`–`0020`) have snapshots/journal; versioned validation ledgers, policy, operations/recovery docs and synthetic PostgreSQL CI explain evidence boundaries. Good engineering-pattern reference, not code to transplant wholesale.

## StoryNest: concrete findings

| Priority | Finding and source evidence | Replacement requirement |
| --- | --- | --- |
| High | **Private reading activity is disclosed.** Add writes activity regardless of visibility (`server.js:1603`); every update with completed status writes title/name (`1731–1733`); authenticated global feed returns all activities without visibility/owner filtering (`2750–2759`). | Private by default, explicit publication policy; public feeds derive only from currently public entries and remove/fence events after privacy changes. |
| High | **Shared search corpus mixes private metadata and catalog identity.** Every created/updated story syncs into the shared index (`1605–1606`, `1735–1736`, `710–739`); search joins that index to stories and returns rating/metadata without visibility checks (`825–862`). Canonical external rows retain one nullable `story_id`; deleting that user's story cascades deletion of the shared row (`database.js:193`, `219`, `246`). | Canonical catalog owns public/provider metadata; private library entries never supply global descriptions, aliases, ratings or covers implicitly. Search documents reference works, not an arbitrary user's copy. |
| High | **Unsafe administrator bootstrap/authority.** Default seed password is `admin123` (`server.js:15–16`), startup creates/promotes by configured email (`167–178`, `2881`), and authorization/login infer admin from email (`161–164`, `1123`). Registration/email change do not reserve that identity (`1071–1093`, `1249–1272`). Occupied seed email reduces the ordinary path, but bootstrap races/failure or a vacated address remain dangerous; existing tokens retain role/email for seven days. | Explicit one-time privileged provisioning, no default password or email-derived authority, fresh server-side role checks and revocable sessions. |
| High | **Image proxy is not a strict allowlist.** Any image-looking domain passes (`server.js:65–72`); lexical private-IP checks do not validate DNS resolution or redirect destinations. Fetch follows redirects and allocates the complete body before enforcing 6 MB (`74–86`). | Exact HTTPS provider allowlist, redirect revalidation/disabled redirects, network egress controls, streamed byte limit and timeout; disallow arbitrary user-selected fetch targets. |
| High | **Database TLS certificate verification disabled** for nonlocal SSL (`database.js:19–28`). | Validate provider certificates/CA; fail closed on invalid TLS configuration. |
| Medium | **Non-atomic duplicate and index updates.** Library duplicate detection precedes insert (`server.js:1537–1570`), while owner/external indexes are nonunique (`database.js:239–240`). Explicit rereads are supported but cannot distinguish accidental concurrent duplicates reliably. Index upsert performs select/delete/update/insert without transaction or conflict handling (`server.js:651–707`), despite external unique index. | Separate one library entry per user/work from reading sessions/rereads; unique constraints, transaction-based upserts and deterministic conflict responses. |
| Medium | **Weak validation and mutation semantics.** Chapters/ratings use coercion and NaN/range checks, not finite/integer validation (`server.js:1506–1514`, `1661–1669`); total chapters can become NaN, whitespace titles pass initial truthiness, and reread parent has no FK (`database.js:74`). Pin/favorite and reactions are read-then-toggle (`2703–2723`, `2266–2286`); retries can reverse intent and concurrent reactions can hit uniqueness errors. | Strict schemas and DB checks; string IDs across API boundaries; explicit set/unset endpoints with idempotency and owned FK checks. |
| Medium | **DDL at runtime and incomplete migration history.** App initializes tables/indexes lazily at startup/request (`server.js:26–41`, `113–134`); `initDatabase` is sequential unversioned DDL. Trigram index errors are swallowed (`database.js:247–252`); migration script reuses initialization and loops through backfills (`scripts/migrate.js:1`, `47–59`). | Explicit ordered immutable migrations, capability/readiness verification, bounded backfills, cold-install and upgrade tests. |
| Medium | **Community keyed by normalized title, not work ID.** Discussions/posts hold free-text `title_key` without catalog FK (`database.js:126–155`), and any authenticated user creates arbitrary keys (`server.js:2032–2045`, `2215–2226`). Accent/punctuation normalization collapses distinct works; alternate titles split one work. Legacy discussions/likes and newer posts/comments/reactions coexist. | One canonical work hub and one thread model; explicit migration of legacy discussions; abuse controls, moderation and stable work relations. |
| Medium | **Auth/error exposure and limited verification.** Browser JWT storage is documented as localStorage (`README.md:97`); password change does not revoke tokens (`server.js:1333–1357`); errors expose driver messages (e.g. `1608–1609`). Server middleware shows open CORS/8 MB JSON with no auth throttling (`43–44`). Tracked tests cover genre/search mapping/ranking, not auth/privacy/CRUD/database races. | HttpOnly secure sessions, logout/password-change revocation, throttling, generic client errors and security/integration tests. |

### MangaDex and search-specific lessons

Preserve the good ideas: real localized provider titles/aliases rather than hand-authored synonym maps, original plus accent-folded queries, exact external-ID deduplication, timeout-bounded provider calls, DB-first results, language-aware display titles and metadata-quality-aware merges (`services/mangadex.js:40–62,150–217,292–301`; `mangaSearchService.js:119–201,261–306`; `server.js:597–648`).

Do not copy these defects:

- Normalization/deduplication is repeated in server, both services and migration script (`server.js:219–228`; `mangaSearchService.js:11–35`; `mangadex.js:14–38`; `scripts/migrate.js:3–33`). Consolidate and version it; preserve original locale-tagged titles in relational rows/JSON arrays rather than slash-separated text.
- Provider cache stores failures/empty results for **24 hours**, then reports cached entries with `error: null` (`mangadex.js:267–304`). Outer service additionally caches empty/error results for ten minutes (`mangaSearchService.js:339–341,398–399`). Separate negative results from transient failures and use short bounded failure cooldowns.
- Process-local Maps have no capacity bound/global coordination; expired provider keys are not removed globally. Concurrent searches do not collapse; the outer `Promise.race` does not cancel underlying work (`mangaSearchService.js:344–349`). Lazy enrichment/inflight state is also process-local and fire-and-forget (`server.js:958–1006`), unreliable across serverless suspension or replicas. Use bounded cache, abort propagation, distributed rate limits and durable jobs if refresh correctness matters.
- `pickLocalizedValue` falls back to *any* language, so missing VI can become English labelled Vietnamese (`mangadex.js:68–77,182–184`). Preserve missing locales; make fallback explicit in display projection rather than stored provenance.
- `lastChapter` is coerced numerically (`mangadex.js:103–105,214`) but library columns are integers; fractional/special chapter labels need separate ordinal/label or deliberate constraints.
- Search permits `erotica` while excluding `pornographic`; tests deliberately encode this (`tests/mangaSearchService.test.js:58–66`). Content policy must be explicit, user-filtered and consistently applied to search **and detail/import**, not assumed safe from the search endpoint alone.
- README claims incomplete metadata is synchronously enriched before response (`README.md:198`), but current code labels syncing and queues background refresh (`server.js:1009–1027`). Treat implementation as authoritative and update contracts/tests together.

## Eiren: reusable principles and bounded risks

**Strong source-backed patterns**

1. **Manifest-driven modular monolith:** optional modules default disabled; manifest registration rejects duplicate keys/commands/components, missing core and dependency cycles (`src/app/registry.ts:38–115`). Copy cohesive domain boundaries and centralized composition, not Discord module names or a plugin framework before needed.
2. **Validated startup configuration:** Zod bounds flags, URLs, ports and credentials; HTTPS is mandatory except explicit loopback; validation errors disclose field names only (`src/core/config/env.ts:8–35,61–108`).
3. **Fresh, scoped authorization:** role mappings cannot grant owner authority (`src/core/permissions/permission-service.ts:10–28`); dashboard discovery is not authorization, and live guild/member/role retrieval fails closed (`src/dashboard/access/dashboard-access.ts:8–32`). Tests explicitly cover IDOR, role removal, absent membership and role-fetch failure (`dashboard-access.test.ts:31–67`). Adapt to TaleAtlas resource ownership/current account roles, not Discord roles.
4. **Revocable session design:** cryptographic tokens, DB-stored SHA-256 hashes, HttpOnly/SameSite cookies, idle/absolute expiry, logout revocation and timing-safe CSRF HMAC (`src/dashboard/auth/dashboard-auth.ts:31–35,48–52,94–123`).
5. **Transactional invariants:** event creation/reminders are atomic; RSVP capacity and duplicate membership are serialized with row locks and presentation state (`src/modules/events/repository.ts:11–17,47–78`). This directly informs library uniqueness, progress writes and reaction state.
6. **Explicit migrations and synthetic verification:** migrator is a separate entry point with sanitized errors (`src/app/migrate.ts:6–19`); CI pins tooling/frozen lockfile, enforces synthetic-only credentials, verifies empty DB, runs typecheck/tests/build/cold migrations/DB suites/dashboard/restore (`.github/workflows/ci.yml:39–115`). Validation ledgers separate source, synthetic DB and live evidence rather than declaring everything production-ready.

**Risks/limits to avoid importing blindly**

- External network work inside DB row-lock transactions can prolong contention: `EventRepository.syncAnnouncement` calls `await publish(...)` while holding an update lock (`src/modules/events/repository.ts:81–95`). Prefer committed intent/outbox, bounded external work, conditional receipt and reconciliation; do not promise exactly-once external delivery.
- OAuth state is process-local (`dashboard-auth.ts:38–40,56–76`): replicas/restarts need sticky routing or shared durable nonce storage. Authorizing every guild via repeated live REST calls (`dashboard-access.ts:35–45`) is fail-closed but can become latency/rate-limit pressure.
- Dispatcher member fetch does not explicitly force cache bypass, unlike dashboard access (`src/core/commands/dispatcher.ts:39`; dashboard-access.ts:15–21`). Do not assume every entry point has identical freshness guarantees.
- Migration tooling calls full `loadEnv`, requiring Discord-shaped config even for a DB-only command (`src/app/migrate.ts:6`; env.ts:26–30). TaleAtlas DB tooling should validate only its own requirements.
- AI production provider is deliberately absent; dashboard remains opt-in; privacy erasure is partial/database-only; synthetic restore is not production recovery. These are explicit boundaries, not missing implementations to present as complete (`README.md:118–140,154–166`; `V8-VALIDATION.md:26–28`). Historical PASS counts in ledgers are not a test run of this audit.
- Eiren's extensive policy/retention/automation machinery exceeds an initial reading MVP. Reuse bounded jobs, metadata-only audit and confirmation principles proportionally, not the entire operational surface.

## Proposed TaleAtlas replacement

Build a **TypeScript modular monolith with PostgreSQL**, strict runtime schemas, explicit migrations and a component-based web client. Keep transport/controllers thin; domains own policy/services and repositories own scoped queries. Start with identity, catalog, library/progress, search/provider adapter and communities; isolate external integrations and operational tooling.

Suggested core model:

- `users`, revocable `sessions`, explicit account roles and preferences.
- `works` with stable internal IDs; `work_external_ids` unique on provider/external ID; locale-tagged `work_titles`, contributors and genres; metadata provenance/freshness/content rating.
- `library_entries` unique on `(user_id, work_id)` with visibility, status, rating, favorite/pin and private note. Separate `reading_sessions`/progress events represent intentional rereads; chapters support known total vs unknown and special labels deliberately.
- `communities`/threads/posts/comments/reactions reference `work_id`; permissions/moderation are explicit. Public projections exclude private notes/progress by construction. Activity publication is opt-in and privacy-aware.
- Search documents derive from canonical **public catalog metadata**. Owner-library search is a separate scope. Normalize once, keep original titles, use trigram/full-text indexes with verified capabilities and quality-ranked results.
- Bounded provider cache and request collapse; short negative TTL versus transient failure cooldown; global provider concurrency/rate budget, abortable deadlines, strict image egress, durable refresh intents with leases if asynchronous enrichment is required. Imported user overrides stay user-local unless reviewed/published.

**Delivery gates:** fresh DB install + upgrade fixture preservation; session revocation and role-change denial; cross-user/private-field isolation including feeds/search; concurrent same-work import and explicit reread; finite/integer/range validation; idempotent favorite/reaction updates; MangaDex locale/content/timeout/failure-cache fixtures; SSRF/redirect/stream limits; pagination and query-plan checks; bounded readiness and a documented synthetic restore. Never execute reference migration or health scripts against unknown databases.

**Recommendation:** retain StoryNest's product vocabulary and bilingual catalog-search UX; adopt Eiren's typed boundaries, authorization discipline, immutable migrations and honest evidence ledgers; replace StoryNest's shared per-user story/catalog schema, token/seed authority, runtime DDL and best-effort concurrency rather than extending them.
