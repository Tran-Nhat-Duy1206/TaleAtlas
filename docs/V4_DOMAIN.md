## Typed model and identity

Use five additive tables, explicit columns/enums/checks, not unrestricted evidence JSON:

1. `community_contents`: stable UUID; canonical Work UUID; `THREAD`/`REPLY`/`REVIEW`; server-derived text user identity (nullable ONLY after account erasure); separate author state `ACTIVE`/`DELETED`/`ERASED` and moderation state `VISIBLE`/`HIDDEN`; plain title/body, independent title/body spoiler flags and optional explicit context; optional integer half-star rating; positive revision, bounded event/report counters; actual creation/edit/activity timestamps. No cached author name, email, Work metadata or original-text snapshots.
2. `community_content_events`: target UUID/Work/kind composite scope, actor user FK, unique target/revision, typed command and before/after author/moderation states, timestamp. Metadata only: no old/new body/title/rating/private facts, arbitrary JSON or actor snapshot. Private moderation history; no public history adapter.
3. `community_reports`: stable UUID; scoped content UUID+Work+kind FK, signed reporter FK; explicit reason enum and bounded plain explanation; OPEN/DISMISSED/UPHELD, positive revision and actual timestamps; unique open reporter/target. Never public reporter/reason/explanation.
4. `community_moderation_actions`: stable UUID; target UUID+Work+kind FK; signed moderator/admin FK; optional report scoped by report UUID+Work+target+kind; DISMISS/HIDE/RESTORE; mandatory bounded plain reason except explicitly redacted erasure evidence; typed sequence/revision metadata and timestamps. No content snapshots; never public reasons/actor/report identity.
5. `community_mutation_receipts`: signed actor FK, Work UUID, target UUID/kind, optional report UUID, UUID mutation key, SHA256 request hash, typed command/outcome metadata and timestamp. One actor/key namespace across all V4 commands; no copied payload or authored text. V4 is separate from V3's key namespace but shares the unchanged application write budget.

Work existence is not publication eligibility. Every ordinary public fetch/list/count/create/edit/replay/reveal/aggregate requires currently PUBLISHED Work in its own coherent transaction. Hidden/draft/missing/unpublished Work yields generic not-found, no title/metadata/community body/count/search excerpt. Moderator PRIVATE queues may retain report/content evidence for an unavailable Work, but expose only Work UUID/unavailable context, NOT hidden catalog title/metadata; moderation grants no catalog publication/editorial privileges. ## Thread/reply structure

Threads alone have nonempty titles (1–160) and bodies (1–8000); no public rating or reply scope. Replies have plain body1–4000, no title/rating, required THREAD target and same Work; root reply depth0, nested depth1–2, maximum three reply levels. Parent is optional only at depth0. Nested parent must be a REPLY in the exact SAME Work AND thread with depth exactly childDepth-1. Composite unique/FKs include ID, Work, thread, kind and parent depth; a bare parent UUID is insufficient. Thread/parent/Work/kind/owner binding is immutable after creation (owner may only become null through erasure). Cycles are impossible with strict decreasing depth. No fake chapter inventory/context inference.

Reply creation locks eligible Work, thread and parent; ordinary roots must be active/visible. A deleted/erased reply remains a non-identifying structural parent for surviving replies, but cannot receive new replies. Moderator-hidden threads hide their entire public conversation; moderator-hidden replies hide their descendant branch. Public placeholders may distinguish deleted and moderator-removed states but never include hidden body/title/author/reasons. Thread activity is a timestamp of a real accepted posting/edit action; no view/like/engagement counters are fabricated. Pagination uses stable timestamp+UUID order, never mutable popularity estimates.

## Spoiler delivery, not CSS masking

Title and body spoiler flags are independent; replies/reviews have their own body flag regardless of parent. Context is an optional independently validated plain label (<=80), never a fabricated chapter/volume/reading total. Non-null context requires a spoiler flag and is hidden with the spoiler, since labels themselves can spoil.

Initial hidden-mode SSR/RSC/JSON/list previews contain NO spoiler text/context: null/typed masked state and fixed localized placeholders only. No hidden markup, aria/title/data attributes, links/slugs, metadata/OG/JSON-LD, excerpts or search indexes carrying that text. Community routes use generic metadata, never authored user text. No automatic reveal via prefetch, hydration or parent reveal. Explicit user action makes a bounded same-origin reveal request specifying scope and expected content revision plus acknowledgment; server rechecks gate, Work/content/ancestor visibility and revision before returning only that selected public text. It is a read, not a write or a private-library access. Safe plain text appears only after successful explicit action; refreshed revisions revert to masked state. Revealing a parent never reveals independently tagged children. Spoiler protection is opt-in concealment, not encryption/access control against an explicit reader.

Public catalog→discussion-list and discussion-list→conversation ingress uses ordinary same-origin document links, not prefetched/intermediate client-RSC transitions. Their single intended navigation starts from a freshly authorized masked SSR document before interactive ownership/editor state. This is uniform application behavior, not a test-only warmup, extra reload or user-agent bypass. Existing revision/SSR replacement still remasks and clears stale editor/acknowledgment state; no reveal cache, private history or authored editor content is hydrated across this boundary.

Interactive community controls stay disabled in SSR and initial hydration until their client handlers are installed. A stable `useSyncExternalStore` readiness snapshot is false on the server/initial hydration and true on the client; it does not fetch, reveal, post, delay or prefill anything. Hydration only permits subsequent explicit actions; all current ownership, visibility, revision, budget and acknowledgment gates remain independently required. This prevents presenting a clickable server control whose action would be lost before hydration.

## Authority, transactions, races and budgets

All writing requires a real signed Better Auth session and verified email; moderator actions additionally require persisted server-owned moderator/admin, never client input or UI-only guards. Identity-bearing V4 budget upserts use a short transaction that locks/revalidates persisted user/session before insertion; root account deletion either wins before insertion or waits and erases committed keys. Commit the charged attempt before returning429, never roll it back as part of the later content transaction. Rate rejection does not mutate community state; database failure fails closed. Public read/reveal spam control is separately bounded (60 reads and20 explicit reveals/trusted-proxy client identity/minute; missing/invalid identity shares an unknown bucket), not a write budget. Private moderator-context reads additionally use60/minute per current verified moderator actor, never the write budget. Inside a write transaction, lock/revalidate current user verification/role and current unexpired session identity to serialize role downgrades/revocation, then Work, thread/parent/target, report in deterministic order. Canonical SHA256 binds actor, command, lowercase Work/target IDs, expected revision and already-validated public input. Equal-key/equal-body replay returns CURRENTLY authorized/projected state, never stale body; changed scope/body409. Exact expected content/report revisions prevent lost updates; command+event+receipt+report/moderation status changes commit atomically. Lock both content and report before a resolution; competing decisions conflict. PostgreSQL23505/40001/40P01 become safe409, no arbitrary retry/timeout weakening. Revoked/demoted actors cannot commit based solely on a stale pretransaction check. No user row update grants moderators admin catalog rights.

Ordinary writes cannot edit withdrawn/erased/moderator-hidden content. An author may explicitly withdraw their own hidden text without clearing moderation, including when its Work is unpublished or ancestors hidden. Withdrawal synchronously blanks title/body/context/rating/spoiler flags and identifying public presentation; does not clear HIDDEN or restore publishing. ## Preserved private-library editor revision coordination

Private entry status, reading and personal editors share a page-local metadata-only revision fence. Starting an explicit command synchronously fences sibling editors BEFORE UUID generation/dispatch, and masks old personal/reading input values while a command or revision transition is unsettled. A validated higher-revision result keeps the fence until authoritative refreshed page metadata reaches that revision; existing per-editor revision keys still discard old forms, and personal editing still requires its own validated post-hydration GET. An old editor cannot become usable merely because another editor's refresh has begun or finished independently. No old draft is carried or automatically rebased, and no public/private review coupling is introduced.

The issuing editor alone can manually retry its exact already-frozen pending UUID/body after an ambiguous failure. Definite nonstale failures release only that editor's lease;409 waits for strictly newer authoritative metadata relative to the attempted revision, and401/403/404/removal hold private editors unavailable until the scope unmounts. A valid higher-revision personal GET fences the shared scope without creating a command. Scope state contains revision numbers/flags/opaque local ownership only, never narratives, request bodies or a global actor registry; it performs no network call, automatic navigation, UUID generation or budget reset. Persisted-principal checks, API revision fences, quotas and all original tests/deadlines remain authoritative. This prevents a confirmed preexisting sibling RSC-refresh race from silently replacing a deliberate rating selection with an empty remounted form.
